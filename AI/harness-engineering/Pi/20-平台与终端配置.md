## 1. Windows

### Shell 要求

Pi 在 Windows 上需要一个 bash shell。查找顺序：

1. `~/.pi/agent/settings.json` 里的自定义路径
2. Git Bash：`C:\Program Files\Git\bin\bash.exe`
3. PATH 上任何 `bash.exe`（Cygwin、MSYS2、WSL 都行）

### 推荐方案

普通用户装 [Git for Windows](https://git-scm.com/download/win) 就够了。

### 自定义 shell 路径

想指向别的 bash：

```json
{
  "shellPath": "C:\\cygwin64\\bin\\bash.exe"
}
```

### 已知问题

文档只点了 bash shell 这一个依赖。原文："Pi requires a bash shell on Windows."——没有其它 Windows 特有问题或终端推荐。

Windows Terminal 的 `Shift+Enter`、`Alt+Enter` 默认会触发系统快捷键，要让 Pi 正常用得手动改键，见下面 [[#5-terminal-setup-按终端分项|Windows Terminal]] 一节。

## 2. Termux（Android）

Termux 是 Android 上的终端模拟器 + Linux 环境，Pi 能在上面跑。

### 前置依赖

两个 app 都要装（推荐 **GitHub 或 F-Droid**——Google Play 上的版本已 deprecated）：

1. **Termux**——终端模拟器本身
2. **Termux:API**——剪贴板等系统集成所需

### 安装步骤

```bash
pkg update && pkg upgrade
pkg install nodejs termux-api git
npm install -g --ignore-scripts @earendil-works/pi-coding-agent
mkdir -p ~/.pi/agent
pi
```

`--ignore-scripts` 在 Termux 上特别重要——native binary 限制见下。

### 剪贴板支持

文本剪贴板靠 `termux-clipboard-set` 和 `termux-clipboard-get`，要装 Termux:API app。**图片粘贴（ctrl+v）在 Termux 上不支持**。

### 推荐 AGENTS.md

建议在 `~/.pi/agent/AGENTS.md` 里告诉 agent Termux 环境信息：

| 路径 | 含义 |
|------|------|
| `/data/data/com.termux/files/home` | Home 目录 |
| `/data/data/com.termux/files/usr` | Prefix |
| `/storage/emulated/0` | Shared storage |

也建议列出常用 `termux-*` 命令：打开 URL/文件、通知、剪贴板、电池/WiFi/设备信息、分享、toast、震动、TTS、相机等。

### 已知限制

- **No image clipboard**——只支持文本
- **No native binaries**——Android ARM64 上某些原生依赖（如 clipboard 模块）被跳过
- **Storage access** 需要先跑 `termux-setup-storage` 授权一次

### 排错

| 现象 | 处理 |
|------|------|
| 剪贴板不工作 | 确认装了 Termux 和 Termux:API 两个 app，再 `pkg install termux-api` |
| shared storage permission denied | 跑 `termux-setup-storage` |
| Node.js 安装出问题 | `npm cache clean --force` |

## 3. Terminal Setup：按终端分项

Pi 依赖 Kitty 键盘协议来准确识别 modifier 按键。许多现代终端原生支持；其它的要配置。

### 3.1 Kitty 和 iTerm2

无需任何配置，直接能用。

### 3.2 Apple Terminal

Pi 会自动启用 enhanced key reporting。Terminal.app 发送 plain Return 表示 Shift+Enter 时，Pi 用本地 macOS modifier check 兜底解释。

**限制**：兜底要求 Pi 跑在 Terminal.app 所在的同一台 Mac 上——**不跨 SSH 工作**。

### 3.3 Ghostty

编辑 Ghostty 配置：

| OS | 路径 |
|----|------|
| macOS | `~/Library/Application Support/com.mitchellh.ghostty/config` |
| Linux | `~/.config/ghostty/config` |

加上：

```text
keybind = alt+backspace=text:\x1b\x7f
```

如果之前为旧版 Claude Code 加过 `keybind = shift+enter=text:\n`，可以删掉（除非还在 tmux 里用 Claude Code）。那个映射发送 raw linefeed，Pi 和 tmux 没法把它跟 Ctrl+J 区分开。

要让 Shift+Enter 仍能用这个 remap，更新 `~/.pi/agent/keybindings.json`：

```json
{
  "newLine": ["shift+enter", "ctrl+j"]
}
```

### 3.4 WezTerm

新建 `~/.wezterm.lua`：

```lua
local wezterm = require 'wezterm'
local config = wezterm.config_builder()
config.enable_kitty_keyboard = true
return config
```

### 3.5 VS Code 集成终端

`keybindings.json` 位置：

| OS | 路径 |
|----|------|
| macOS | `~/Library/Application Support/Code/User/keybindings.json` |
| Linux | `~/.config/Code/User/keybindings.json` |
| Windows | `%APPDATA%\Code\User\keybindings.json` |

加入多行输入（Shift+Enter）：

```json
{
  "key": "shift+enter",
  "command": "workbench.action.terminal.sendSequence",
  "args": { "text": "[13;2u" },
  "when": "terminalFocus"
}
```

### 3.6 Windows Terminal

打开 `settings.json`（Ctrl+Shift+, 或菜单），在 `actions` 数组加：

```json
{
  "command": { "action": "sendInput", "input": "[13;2u" },
  "keys": "shift+enter"
},
{
  "command": { "action": "sendInput", "input": "[13;3u" },
  "keys": "alt+enter"
}
```

要点：

- Shift+Enter 触发换行
- **Alt+Enter 默认是全屏快捷键**——阻挡 Pi 的 follow-up 队列功能
- 上面的 remap 把按键转发给 Pi
- 老的全屏行为还在的话，**完全重启** Windows Terminal

### 3.7 xfce4-terminal 和 terminator

escape sequence 支持有限：原文 "Modified Enter keys like `Ctrl+Enter` and `Shift+Enter` cannot be distinguished from plain `Enter`"——所以 `submit: ["ctrl+enter"]` 这类自定义键位不工作。

**推荐替代**（支持 Kitty 协议）：

- Kitty
- Ghostty
- WezTerm
- iTerm2
- Alacritty（需编译时打开 Kitty 协议支持）

### 3.8 IntelliJ IDEA 集成终端

escape sequence 支持有限，Shift+Enter 和 Enter 区分不开。

**硬件光标**：设 `PI_HARDWARE_CURSOR=1` 再启动 Pi（默认关，为了兼容性）。最佳体验还是用独立终端模拟器。

## 4. Shell Aliases

### 问题

Pi 用非交互模式跑 bash（`bash -c`）——这种模式下 bash **默认不展开 alias**。

### 解法

在 `~/.pi/agent/settings.json` 里配置 shell command prefix，启用 alias 展开并 source 现有 alias：

```json
{
  "shellCommandPrefix": "shopt -s expand_aliases\neval \"$(grep '^alias ' ~/.zshrc)\""
}
```

这个 prefix 干两件事：

1. 打开 `expand_aliases` shell 选项
2. 从 shell 配置文件里 grep alias 定义，eval 它们

### 调整

按用的 shell 改配置文件路径——`~/.zshrc`、`~/.bashrc` 或其它 rc file。

> **文档没有列任何 Pi 专属的推荐 alias**，只讲了"怎么让已有 alias 在 Pi 里生效"。
