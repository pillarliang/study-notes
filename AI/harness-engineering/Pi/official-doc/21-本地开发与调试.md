# 14 - 本地开发与调试

> 来源：https://pi.dev/docs/latest/development

面向想给 Pi 本身贡献代码、或者要 fork/rebrand Pi 的开发者。

## 1. Setup

```bash
git clone https://github.com/earendil-works/pi-mono
cd pi-mono
npm install
npm run build
```

直接用源码跑 Pi：

```bash
/path/to/pi-mono/pi-test.sh
```

`pi-test.sh` 从任意目录都能调用——文档原话："Pi keeps the caller's current working directory."（保留调用方的工作目录）。

## 2. Fork / Rebrand

通过 `package.json` 里的 `piConfig` 块定制：

```json
{
  "piConfig": {
    "name": "pi",
    "configDir": ".pi"
  }
}
```

要 rebrand fork：改 `name`、`configDir`，以及 `bin` 字段。这些值会流到：

- CLI banner
- 配置路径
- 环境变量命名

## 3. 路径解析

Pi 在三种执行上下文里运行：

1. npm install 后调用
2. standalone binary
3. 通过 tsx 直接从源码跑

为了统一处理这三种场景，**访问 package 资源时要用 `src/config.ts` 的 helper**：

```ts
import { getPackageDir, getThemeDir } from "./config.js";
```

文档强调：**不要直接用 `__dirname`** 访问 package 资源。

## 4. 调试命令

隐藏的 `/debug` slash 命令把诊断信息写到 `~/.pi/agent/pi-debug.log`，包括：

- 渲染过的 TUI 输出（含 ANSI escape sequences）
- 最近发给 LLM 的 message payload

## 5. 测试

| 命令 | 说明 |
|------|------|
| `./test.sh` | 跑非 LLM 测试（不需要 API key） |
| `npm test` | 全部测试 |
| `npm test -- test/specific.test.ts` | 跑指定测试文件 |

`./test.sh` 适合没有 provider API key 的贡献者。

## 6. Monorepo 结构

四个 package 分层：

```text
packages/
  ai/           # LLM provider 抽象
  agent/        # agent loop 和消息类型
  tui/          # 终端 UI 组件
  coding-agent/ # CLI 和交互模式
```

这种分层把 provider 层、agent 编排、终端渲染、CLI 入口作为独立关切。
