# 学习指南修订方案：真实例子驱动

适用对象：本文件夹全部编号学习指南（00–23）。目标：消除"官方文档能看懂、学习指南反而难懂"的章节。

## 病根诊断

难懂章节的共同点：把官方文档用例子讲清的内容，重新抽象成规则叙述，读者被迫在脑中自行重建例子。典型症状：

- 进例子之前先自造术语体系（"参与方有三个：……"）或铺场景剧本；
- 连续多段纯规则叙述，例子迟迟不出现；
- 例子只是规则的"附件"，而不是讲解的主线。

对照：官方文档讲 resume 子 agent，结构是「一句话说明 → 两个 id 从哪来 → 三步操作 → 一段完整可运行代码 → 三条持久化规则」——例子和代码是主线，规则只做收束。

## 每节写作模板（与官方文档结构对齐）

0. **篇首标来源**——章标题正下方一行 `> 来源：[官方页标题](URL)`，多个页面用、分隔；URL 从官方 llms.txt 索引核对，不凭记忆写。
1. **一句话立目标**——这节解决什么问题，不超过两句，不铺场景剧本。
2. **真实例子做主线**——贴一次真实运行的消息/输出（裁剪到关键字段，保留真实 id 与真实值），逐段旁注"这是什么、从中取什么"。概念在例子中首次出现处就地引入，不提前集中定义。
3. **完整代码**——可运行的最小示例，中文注释指认关键行；优先改写官方示例。
4. **规则收束**——前提、边界条件用短 bullet 或表格放在最后，只收束例子已经展示过的内容。

## 代码放哪：code cell vs markdown fenced block

notebook 的价值就在 cell 可执行，按可运行性分流：

- **完整可运行示例**（import 齐全、无未定义名字、跑起来有意义）→ 必须放**独立 code cell**，读者一键执行。全放 markdown fenced block 的话，这个文件就不如直接写成 `.md`。
- **不可运行的示意** → 留在 markdown fenced block：真实消息实例的转录（`ResultMessage(...)` 之类）、依赖未定义名字的配置片段、协议骨架、目录树。
- 判别法：把这段代码原样贴进空 kernel 能不能跑？能跑 → code cell；不能 → markdown，且不要为了"看起来能跑"补假定义。

## cell 粒度：一个章节一个 cell

- 每个章节标题（`##` / `###`）独立成一个 markdown cell；一个 cell 不得跨两个章节。
- 章首 = `## N` 标题 + 导语合为一个 cell。
- 章节内插 code cell 时，code cell 之后的收束文字（如"三条边界"）单独成 markdown cell，仍属该章节。
- 批量拆分用脚本按标题行切（fenced block 内的 `#` 行不算标题），并断言拆分前后内容逐字拼接一致。脚本：

```python
#!/usr/bin/env python3
"""把 notebook 的 markdown cell 按章节标题（##/###/####）拆成独立 cell。

- code cell 原样保留（含输出）
- fenced code block 内的行不作为切分点
- 断言：每个 md cell 拆分后各段拼接 == 原文，保证零丢失
用法：python3 split_notebook_sections.py <a.ipynb> <b.ipynb> ...
"""
import json
import sys
import uuid
from pathlib import Path


def split_markdown(lines):
    """按标题行切分，返回若干段（每段为行列表）。"""
    segments = []
    current = []
    in_fence = False
    for line in lines:
        stripped = line.lstrip()
        if stripped.startswith("```") or stripped.startswith("~~~"):
            in_fence = not in_fence
            current.append(line)
            continue
        is_heading = (not in_fence) and line.startswith("##") and line.lstrip("#").startswith(" ")
        if is_heading and any(l.strip() for l in current):
            segments.append(current)
            current = [line]
        else:
            current.append(line)
    if any(l.strip() for l in current):
        segments.append(current)
    return segments


def to_lines(source):
    if isinstance(source, str):
        return source.splitlines(keepends=True)
    return list(source)


def process(path):
    nb = json.loads(Path(path).read_text())
    new_cells = []
    changed = False
    for cell in nb["cells"]:
        if cell["cell_type"] != "markdown":
            new_cells.append(cell)
            continue
        lines = to_lines(cell["source"])
        segments = split_markdown(lines)
        assert "".join(l for seg in segments for l in seg) == "".join(lines), f"{path}: 内容不一致"
        if len(segments) <= 1:
            new_cells.append(cell)
            continue
        changed = True
        for i, seg in enumerate(segments):
            while seg and not seg[-1].strip():
                seg.pop()
            new_cells.append({
                "cell_type": "markdown",
                "id": cell["id"] if i == 0 else uuid.uuid4().hex[:8],
                "metadata": dict(cell.get("metadata", {})),
                "source": seg,
            })
    if changed:
        nb["cells"] = new_cells
        Path(path).write_text(json.dumps(nb, ensure_ascii=False, indent=1) + "\n")
    print(f"{'SPLIT ' if changed else 'keep  '}{Path(path).name}")


if __name__ == "__main__":
    for p in sys.argv[1:]:
        process(p)
```

## 真实实例的来源（按优先级）

1. 本 notebook 已执行 cell 的真实输出；
2. 真实会话采集的消息流记录（如用户提供的运行日志）；
3. 官方文档中的示例（视为合格锚点）；
4. 都没有 → 写一个"采集 cell"（运行后打印原始消息流），标注待运行；**禁止虚构 id/值冒充真实数据**。

## 禁止项

- 自造术语体系开场，再让读者带着术语进例子；
- 连续三段以上无代码、无实例的规则叙述；
- 官方文档本来例子驱动的章节，改写成纯规则版；
- 假 id、占位值伪装成真实运行数据（官方示例中的示意值除外，但要能区分）。

## 自检法

逐节问四个问题：

1. 官方文档对应章节怎么讲的？它用了例子，这一节的例子在哪？
2. **官方页的每一段示例代码，指南里是否都有对应的 code cell？**把官方代码"化成叙述"即违规——对计算机行为最清晰的说明就是代码本身。修订前先列官方页的代码示例清单，逐条勾对。
3. 删掉所有例子和代码后这节还剩几段？剩三段以上说明规则堆太多；
4. 例子里的值是真的吗？能指出它来自哪次运行、哪篇官方文档吗？

## 批量修订流程

1. 逐文件审计，按上面标准列出违规小节（文件、cell、小节标题、违规类型）；
2. 每个违规小节按模板重写：优先复用该 notebook 已有的执行输出做锚点；
3. 一次只改一个文件，改完确认 notebook JSON 结构完整（cell 顺序、id 不乱）；
4. VSCode 中打开着的 notebook 先关闭再改，避免保存竞态；乱序后整本重建，不逐 cell 修补。
