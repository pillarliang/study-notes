# Pydantic BaseSettings



### 1. 基本概念

`pydantic-settings` 是 Pydantic v2 的配置管理扩展，用于从环境变量、.env 文件等外部源加载配置。

```bash
pip install pydantic-settings
```



### 2. BaseModel vs BaseSettings


| 特性          | BaseModel | BaseSettings |
| ----------- | --------- | ------------ |
| 数据验证        | ✅         | ✅            |
| 从环境变量加载     | ❌         | ✅            |
| 从 .env 文件加载 | ❌         | ✅            |
| 用途          | 数据模型      | 配置管理         |


```python
from pydantic import BaseModel
from pydantic_settings import BaseSettings, SettingsConfigDict

# BaseModel: 不会读取环境变量
class UserModel(BaseModel):
    name: str = "default"

# BaseSettings: 自动读取环境变量
class AppSettings(BaseSettings):
    name: str = "default"  # 会尝试从 NAME 环境变量读取
```



### 3. 环境变量前缀

使用 `env_prefix` 避免环境变量命名冲突：

```python
class DatabaseConfig(BaseSettings):
    host: str = "localhost"
    port: int = 5432

    model_config = SettingsConfigDict(
        env_prefix="DATABASE_",  # 环境变量需要以 DATABASE_ 开头
        case_sensitive=False,    # 不区分大小写
    )

# 对应环境变量:
# DATABASE_HOST=127.0.0.1
# DATABASE_PORT=3306
```



### 4. 字段别名 (alias)

当环境变量名与字段名不同时使用：

```python
from pydantic import Field

class RedisConfig(BaseSettings):
    # 字段名是 host，但环境变量是 REDIS_IP
    host: str = Field(default="localhost", alias="ip")

    model_config = SettingsConfigDict(
        env_prefix="REDIS_",
        populate_by_name=True,  # 允许同时使用字段名和别名
    )

# 环境变量 REDIS_IP=127.0.0.1 会映射到 config.host
```



### 5. 嵌套配置

**方式一：嵌套分隔符**

```python
# badcase：
class ContentConfig(BaseSettings):
    enable_cache: bool = True
    max_size: int = 1000

    model_config = SettingsConfigDict(
        env_prefix="APP_CONTENT_",
    )

class AppConfig(BaseSettings):
    content: ContentConfig = Field(default_factory=ContentConfig)

    model_config = SettingsConfigDict(
        env_prefix="APP_",
        env_nested_delimiter="__",  # 使用双下划线分隔嵌套，如果你希望 ContentConfig 能够独立使用，且环境变量格式固定为单下划线，那么父类就不要设置分隔符
    )

# 环境变量:
# APP_CONTENT__ENABLE_CACHE=false(优先级高) # AppConfig (父类) 解析
# APP_CONTENT__MAX_SIZE=2000
# ---
# APP_CONTENT_ENABLE_CACHE=false (优先级低) # ContentConfig (子类)解析
# 不会去解析 APP_CONTENT__APP_CONTENT_ENABLE_CACHE 这种格式。

# good case
# 完全由父类控制（推荐用于严格层级）
# 如果你的目的是想用双下划线 __ 来体现层级，建议把子类改为普通的 BaseModel，不要让子类自己去读环境变量。
from pydantic import BaseModel, Field # 注意这里引入 BaseModel
from pydantic_settings import BaseSettings, SettingsConfigDict

# 1. 子类变成纯数据模型，不负责读取环境变量
class ContentConfig(BaseModel):
    enable_cache: bool = True
    max_size: int = 1000

class AppConfig(BaseSettings):
    content: ContentConfig = Field(default_factory=ContentConfig)

    model_config = SettingsConfigDict(
        env_prefix="APP_",
        env_nested_delimiter="__", # 全权由父类通过分隔符解析
    )

# 必须使用: APP_CONTENT__ENABLE_CACHE=false
```

**方式二：独立 BaseSettings 子类**

```python
class ContentConfig(BaseSettings):
    enable_cache: bool = True

    model_config = SettingsConfigDict(env_prefix="CONTENT_")

class AppConfig(BaseSettings):
    # ContentConfig 自己会从环境变量加载
    content: ContentConfig = Field(default_factory=ContentConfig)

# 环境变量: CONTENT_ENABLE_CACHE=false

## 方法2：
class ContentConfig(BaseSettings):
    enable_cache: bool = True
    max_size: int = 1000
    model_config = SettingsConfigDict(env_prefix="APP_CONTENT_")

class AppConfig(BaseSettings):
    content: ContentConfig = Field(default_factory=ContentConfig)
    
    model_config = SettingsConfigDict(
        env_prefix="APP_", 
        # 不要设置 env_nested_delimiter
    )

# 必须使用: APP_CONTENT_ENABLE_CACHE=false (这是由 ContentConfig 自己读到的)
# 环境变量:
# APP_CONTENT__ENABLE_CACHE=false
# APP_CONTENT__MAX_SIZE=2000

解析逻辑（为什么是这样？）
这里的逻辑不再是“父类帮子类找值”，而是“父类找不到值，子类自己去找”。

1. AppConfig 的尝试（失败）：

AppConfig 初始化。它有前缀 APP_。 它看到字段 content。
因为没有设置嵌套分隔符 (env_nested_delimiter)，AppConfig 只会 去找一个叫 APP_CONTENT 的环境变量（期望它是一个 JSON 字符串，比如 '{"enable_cache": false}'）。如果没有定义 APP_CONTENT 这个环境变量，AppConfig 就认为：“好吧，我这边没读到数据”。

2. 回退到 default_factory：

因为 AppConfig 没读到值，它就执行 default_factory=ContentConfig。这相当于在代码里跑了一句：ContentConfig()。

3. ContentConfig 的自启动（成功）：

ContentConfig 被实例化了。因为它也是一个 BaseSettings，它启动时会独立扫描环境变量。它根据自己的配置 env_prefix="APP_CONTENT_" 去查找。它找到了 APP_CONTENT_ENABLE_CACHE。
```



### 6. 配置优先级

默认优先级（从高到低）：

1. **init_settings** - 构造函数传入的值
2. **env_settings** - 环境变量
3. **dotenv_settings** - .env 文件
4. **file_secret_settings** - secrets 目录
5. **默认值** - 字段定义的默认值

**自定义优先级：**`settings_customise_sources`

`settings_customise_sources` 是 Pydantic `BaseSettings` 提供的**类方法钩子（hook）**，让你控制「配置值从哪里来、谁的优先级更高」。

**它能做什么？**

1. **调整默认 4 个源的优先级顺序**
2. **插入自定义配置源**（如从数据库、远程服务、YAML 文件加载）
3. **删除某个源**（比如不想从 .env 读取，直接不返回它）

**如何理解返回值？**

返回一个 tuple，**排在前面的优先级更高**，相同字段以先找到的值为准：

```python
return (
    source_A,   # 最高优先级，先查这里
    source_B,   # A 没有的字段，再查这里
    source_C,   # 以此类推...
)
```

Pydantic 内部的处理逻辑类似于：

```python
# 伪代码：合并多个源的值，先出现的优先
final = {}
for source in reversed(sources):  # 从低优先级开始，高优先级覆盖
    final.update(source())
```

**基本示例：调整默认顺序**

```python
from pydantic_settings import PydanticBaseSettingsSource

class Settings(BaseSettings):
    name: str = "default"

    @classmethod
    def settings_customise_sources(
        cls,
        settings_cls: type[BaseSettings],
        init_settings: PydanticBaseSettingsSource,
        env_settings: PydanticBaseSettingsSource,
        dotenv_settings: PydanticBaseSettingsSource,
        file_secret_settings: PydanticBaseSettingsSource,
    ) -> tuple[PydanticBaseSettingsSource, ...]:
        # 自定义顺序：环境变量 > 初始化值 > .env > 默认值
        return (
            env_settings,
            init_settings,
            dotenv_settings,
            file_secret_settings,
        )
```

**简单示例：让 .env 优先于环境变量**

```python
class Settings(BaseSettings):
    db_host: str = "localhost"

    @classmethod
    def settings_customise_sources(cls, settings_cls, init_settings, 
                                    env_settings, dotenv_settings, 
                                    file_secret_settings):
        return (
            init_settings,
            dotenv_settings,    # .env 排在环境变量前面
            env_settings,       # 环境变量降级
            file_secret_settings,
        )
```

**常见使用场景**


| 场景                                   | 做法                                 |
| ------------------------------------ | ---------------------------------- |
| 接入远程配置中心（AppConfig / Consul / Nacos） | 插入自定义 source 到 tuple 最前面，远程配置优先    |
| 环境变量优先于代码传参                          | 把 env_settings 放到 init_settings 前面 |
| 从 YAML/JSON/TOML 文件读配置               | 写一个自定义 source 读文件，插入 tuple         |
| 禁用某个配置源                              | 从 tuple 中移除它，比如不返回 dotenv_settings |
| 多配置源合并                               | 插入多个自定义 source，按业务需要排序             |


**一句话总结**：`settings_customise_sources` 就是告诉 Pydantic——「别用你默认的加载顺序了，按我给的这个 tuple 顺序来查配置值」。

### 7. 自定义配置源

从外部配置系统（如 AWS AppConfig）加载：

```python
class AppConfigSource(PydanticBaseSettingsSource):
    """从 AWS AppConfig 加载配置"""

    def get_field_value(self, field, field_name) -> tuple:
        return NotImplemented

    def __call__(self) -> dict[str, Any]:
        # 返回配置字典
        return {
            "database": {"host": "prod-db.example.com"},
            "cache": {"enabled": True},
        }

class Settings(BaseSettings):
    database: DatabaseConfig

    @classmethod
    def settings_customise_sources(cls, settings_cls, init_settings, env_settings, dotenv_settings, file_secret_settings):
        return (
            AppConfigSource(settings_cls),  # 最高优先级
            env_settings,                    # 环境变量作为 fallback
            init_settings,
            dotenv_settings,
            file_secret_settings,
        )
```



### 项目实战解析：AWS AppConfig 作为最高优先级配置源

在实际项目中，我们通过 `settings_customise_sources` 将 AWS AppConfig 设置为最高优先级的配置源，实现远程集中式配置管理：

```python
class AppConfigSettingsSource(PydanticBaseSettingsSource):
    """从 AWS AppConfig 加载配置的 Settings 数据源。"""

    def get_field_value(self, field, field_name) -> tuple:
        return NotImplemented

    def __call__(self) -> dict[str, Any]:
        # 从 AWS AppConfig YAML 中读取配置，映射到 Settings 的字段
        return {
            "llm": get_app_config(config_file, "llm_model_config", {}),
            "agent": get_app_config(config_file, "agent", {}),
            "services": get_app_config(config_file, "services", {}),
        }

class Settings(BaseSettings):
    agent: AgentConfig = Field(default_factory=AgentConfig)
    llm: LLMConfig = Field(default_factory=LLMConfig)
    services: ServicesConfig = Field(default_factory=ServicesConfig)

    model_config = SettingsConfigDict(
        env_prefix="PROJECT_SUMMARY_",
        case_sensitive=False,
        extra="ignore",
    )

    @classmethod
    def settings_customise_sources(
        cls,
        settings_cls: type[BaseSettings],
        init_settings: PydanticBaseSettingsSource,
        env_settings: PydanticBaseSettingsSource,
        dotenv_settings: PydanticBaseSettingsSource,
        file_secret_settings: PydanticBaseSettingsSource,
    ) -> tuple[PydanticBaseSettingsSource, ...]:
        return (
            AppConfigSettingsSource(settings_cls),  # 1. AWS AppConfig (最高优先级)
            init_settings,                           # 2. 构造函数传参
            env_settings,                            # 3. 环境变量
            dotenv_settings,                         # 4. .env 文件
            file_secret_settings,                    # 5. secrets 目录
        )
```

**要点总结：**

- `settings_customise_sources` 是 Pydantic BaseSettings 提供的类方法钩子，返回一个 tuple 来定义配置源和优先级
- tuple 中的顺序 = 优先级顺序（第一个最高）
- `AppConfigSettingsSource` 排在第一位，意味着 AWS AppConfig 的远程 YAML 配置可以覆盖所有本地配置
- 这样做的好处：支持远程集中式配置管理 + 热重载（每次调用 `Settings()` 都会重新从 AppConfig 拉取最新配置）
- 如果 AppConfig 加载失败（网络异常等），`__call__` 返回空字典 `{}`，自动降级到后续配置源

### 10. 实际应用示例

```python
from pydantic import BaseModel, Field
from pydantic_settings import BaseSettings, SettingsConfigDict

# 子配置使用 BaseSettings 支持独立的环境变量
class DatabaseConfig(BaseSettings):
    read_uri: str = ""

    model_config = SettingsConfigDict(
        env_prefix="DATABASE_",
        case_sensitive=False,
    )

class RedisConfig(BaseSettings):
    host: str = Field(default="localhost", alias="ip")
    port: int = 6379

    model_config = SettingsConfigDict(
        env_prefix="REDIS_",
        case_sensitive=False,
        populate_by_name=True,
    )

# 聚合配置
class ServicesConfig(BaseModel):
    database: DatabaseConfig = Field(default_factory=DatabaseConfig)
    redis: RedisConfig = Field(default_factory=RedisConfig)

# 主配置
class Settings(BaseSettings):
    services: ServicesConfig = Field(default_factory=ServicesConfig)
    debug: bool = False

    model_config = SettingsConfigDict(
        env_prefix="APP_",
        case_sensitive=False,
    )

# 使用
settings = Settings()
print(settings.services.database.read_uri)  # 从 DATABASE_READ_URI 读取
print(settings.services.redis.host)          # 从 REDIS_IP 读取
```



### 11. 最佳实践

1. **始终设置** `case_sensitive=False` - 环境变量通常是大写的
2. **使用有意义的前缀** - 避免与系统环境变量冲突
3. **子配置用 BaseSettings** - 让每个配置类独立管理自己的环境变量
4. **提供合理的默认值** - 开发环境可以零配置运行
5. **敏感信息用环境变量** - 不要硬编码密钥、密码
6. **文档化环境变量** - 在 docstring 中说明支持的环境变量



# 系统变量



## **os.getenv()**

os.getenv() 是 Python 标准库中用于读取环境变量的函数。这是最直接、最简单的方法。

- **核心原理**：os.getenv() 只会读取**当前进程的环境变量**。
- **关键特点**：
  - 它完全不知道 .env 文件的存在。如果一个变量不在进程环境中，os.getenv() 就找不到它。

```python
# 2. 没有类型转换
port = os.getenv('PORT')  # 返回字符串 "8000"，而不是整数 8000
# 需要手动转换
port = int(os.getenv('PORT', '8000'))
```



### **环境变量的读取优先级：**

1. 显式传参 (Code Level)： `Settings(APP_NAME="force_value")`
2. 操作系统/进程环境变量 (OS/Process Level) (Jenkins 设置的环境变量，优先级最高)
  - 这是 `os.environ` 中实际拿到的值。
    - *来源顺序（谁覆盖谁）：*
      - **Jenkins/K8s/CI 注入** (运行时 `docker run -e` 或 CI 设置) **>**
      - **VS Code** `launch.json` (`env`) **>**
      - **Dockerfile** (`ENV` 指令) **>**
      - **宿主机系统变量**
3. **Dockerfile ENV 指令((File Level)** 设置的环境变量
4. **.env 文件** 中的变量 (优先级最低)
