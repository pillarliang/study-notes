# 英语素材转 YAML

将 `source` 中的英语素材整理为 YAML，写入 `result`。

## 输入与输出

- 输入：素材文件路径，或直接粘贴文本。
- 输出：`result/<源文件名>.yaml`，例如 `source/51.txt` → `result/51.yaml`。
- 直接粘贴文本但未指定文件名时，只需询问文件名。
- 收到素材后直接处理、写入并校验，不重复确认已有规则。

## 处理规则

1. 提取自然、常用、可迁移的英语表达，并保留必要的文化背景。
2. 修正确切可判断的拼写、标点、大小写、语法和不自然表达。
3. 用中文说明用途、语气、场合和限制；英语语块与例句保留英文。
4. 顶层键使用 `daily-communication`，其下按主题和交际功能分类。
5. 每个表达按需使用 `特性`、`结构`、`Example`；没有实际信息的字段直接省略。
6. 所有可替换槽位都用 `[]` 标记，并在标题与结构中保持一致，如 `[holiday]`、`[someone]`；不要用 `...` 代替。
7. 交际功能和触发场景相同的基础形式与扩展形式合并；提供物品、邀请活动、替人做事等不同功能必须分开。
8. 句型或语块需要展示具体用法时才添加 `Example`；完整固定句不重复把标题抄入 `Example`。
9. 只生成一个 YAML 文件，不生成额外学习稿。
10. `特性` 只写影响表达选择的区别：什么情况下用、实际表达什么、什么情况下不能用；一句能说清就不拆成多条，不写“自然、礼貌、常用”等无区分度描述。
11. 原文仅作参考；按真实英语用法判断和纠错，不照抄原文讲解。

## 结构示例

```yaml
daily-communication:
  - "[topic]（中文主题）":
      - "[function group]（中文分类）":
          - "Happy + [holiday]":
              "特性":
                - "用于送上节日祝福。"
              "结构":
                - "Happy + [holiday]!"
              "Example":
                - "Happy New Year!"
```

完成后必须用 YAML 解析器校验，并回复实际输出路径和校验结果。
